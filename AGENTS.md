# Agent Instructions — Avatar Chrome

## What is this project?

Browser-only AI avatar chat app. No backend server. Chrome Built-in AI (Gemini
Nano) generates responses, Piper TTS (Revolab/vits Malay voices) speaks them,
PNGTuber sprites animate with lip-sync. React + Vite + TypeScript.

Inspired by [chrome-on-aituber](https://github.com/shinshin86/chrome-on-aituber)
but stripped to English UI + Malay TTS + PNGTuber avatars only.

## Commands

```bash
npm install              # install deps
npm run dev              # dev server (Vite, port 5173)
npm run build            # production build (tsc + vite)
npm run lint             # ESLint (must pass — zero errors expected)
npm run preview          # preview production build

# One-time setup scripts:
node scripts/prepare-tts.mjs    # copy WASM phonemizer + espeak-ng-data + ONNX Runtime to public/tts/
node scripts/slice-avatar.mjs <sheet.png>  # slice a 2×2 character sheet into 4 PNGTuber sprites
```

## Architecture

### Data flow

```
User input → Chrome Built-in AI (LanguageModel API) → text response
                                                          ↓
                    Piper TTS: text → espeak-ng WASM → phoneme IDs → ONNX Runtime Web → Float32 PCM
                                                          ↓
                    AudioContext playback → AnalyserNode amplitude → mouth level → sprite swap
```

### Key design decisions

1. **No backend server** — TTS runs entirely in-browser via WASM. The
   `piper-phonemize` npm package's WASM binary is loaded via `<script>` tag (not
   bundled by Vite, to avoid WASM resolution issues). espeak-ng-data files are
   fetched at runtime and written into Emscripten's MEMFS virtual filesystem.

2. **TTS is a facade** — `tts/index.ts` delegates to `piper.ts`. To add a new
   engine (e.g., Irodori WebGPU), create a new provider implementing the same
   interface (`isReady`, `initialize`, `synthesize`, `dispose`) and branch in
   the facade. Playback + lip-sync in `playback.ts` are shared.

3. **Speaker management** — Speaker models are discovered from
   `public/tts/models/speakers.json` (auto-generated by `prepare-tts.mjs`).
   Each speaker's ONNX session loads lazily on first use and is cached.
   The user picks a speaker via Settings → "AI & Voice" → Speaker dropdown.

4. **PNGTuber only** — The app swaps between 4 sprites based on mouth level
   (from audio amplitude) and blink state (random timer). To add VRM/PSD/etc.,
   see the original chrome-on-aituber's avatar-runtime/ directory.

5. **System prompt is Malay** — `DEFAULT_SYSTEM_PROMPT` in `types.ts` is in
   Bahasa Melayu because the TTS speaks Malay. English text would produce
   garbled speech through the Malay phonemizer.

6. **React 19 + strict lint** — eslint-plugin-react-hooks v7 is strict about
   refs and setState-in-effect. Don't update `ref.current` during render — use
   `useEffect` or `useCallback` instead. Don't call `setState` synchronously in
   effect body — use lazy initializers (`useState(() => ...)`) or async callbacks.

### Settings shape

```typescript
interface AppSettings {
  appMode: "chat" | "broadcast";       // broadcast = green screen for OBS
  ttsEnabled: boolean;
  selectedAvatarId: string;             // "default" or custom ID
  backgroundImageEnabled: boolean;
  backgroundImageUpdatedAt: number;
  llmSystemPrompt: string;              // Malay by default, editable in Settings
  ttsLengthScale: number;               // 1.0 = normal, >1 = slower, <1 = faster
  ttsSpeaker: string;                   // speaker ID from speakers.json, "" = first
}
```

### How to add a new speaker

1. Download model files from HuggingFace:
   ```bash
   hf download Revolab/vits speakers/NAME/model.onnx speakers/NAME/model.onnx.json --local-dir ./hf-dl
   mkdir -p public/tts/models/NAME
   cp ./hf-dl/speakers/NAME/* public/tts/models/NAME/
   ```
2. Re-run: `node scripts/prepare-tts.mjs` (regenerates speakers.json)
3. The speaker appears automatically in the Settings dropdown

### How to change TTS language

1. Change `PHONEMIZER_VOICE` in `src/services/tts/piper.ts` (e.g., `"en-us"`)
2. Change `DEFAULT_SYSTEM_PROMPT` in `src/types.ts` to match the language
3. Ensure the espeak-ng-data includes the target language's dict and voice files
   (the bundled data includes all espeak-ng languages)

### How to replace the avatar

**Character sheet approach (recommended):**
1. Generate a 2×2 grid image with GPT Image 2 (prompt in `public/avatars/default/README.md`)
2. Run: `node scripts/slice-avatar.mjs path/to/sheet.png`
3. Done — outputs 4 PNGs to `public/avatars/default/`

**Manual:**
Replace the 4 PNGs in `public/avatars/default/` directly. Filenames must match:
`mouth_close_eyes_open.png`, `mouth_close_eyes_close.png`,
`mouth_open_eyes_open.png`, `mouth_open_eyes_close.png`

### Chrome Built-in AI requirements

Users need Chrome 138+ with these flags:
- `chrome://flags/#optimization-guide-on-device-model`
- `chrome://flags/#prompt-api-for-gemini-nano`

If the model isn't downloaded yet, the app shows a "Prepare AI" button.

## Critical constraints

1. **Browser-only** — do not add a backend server. All processing is client-side.
2. **WASM files are loaded via `<script>` tag** — do not `import` them through
   Vite. The Emscripten wrapper and ONNX Runtime are in `public/tts/` and loaded
   by `main.tsx` and `phonemizer.ts`.
3. **CORS headers required in production** — `Cross-Origin-Opener-Policy:
   same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (Vite dev
   server sends these automatically; configure in production hosting).
4. **espeak-ng-data is ~19MB** — first TTS initialization loads these into
   WASM memory. This takes a few seconds. Consider showing a progress indicator.
5. **Lint must pass** — `npm run lint` must return zero errors before committing.
